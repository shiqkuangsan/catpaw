# ADR-0027: Layered CLI Facade

Status: Accepted

Date: 2026-08-14

## Context

ADR-0026 reduced CatPaw's public model to Work, Proof, Approval and four visible
phases, but the executable CLI still led with board storage, internal
mode/stage/Evidence fields, and one overloaded `agent` namespace for both task
intent discovery and provider sessions. It also lacked help, version discovery,
daily progress, and mutation-safe Work progress commands.

The deterministic schema 2 engine, dry-run/apply behavior, JSON reports,
migration, and observable session logic are already sound. Replacing them would
add risk without reducing user concepts.

## Decision

Add a presentation and routing facade over the existing engine:

```text
daily:        status | work | proof | milestone
contracts:    intent
advanced:     board | transport
```

- Human output names Work, Proof, visible Phase, Action, and Next. Stored
  mode/stage/Evidence values remain available in artifacts and JSON.
- `status` is the daily view; `board` owns initialization, diagnostics, and
  migration.
- Work supports `show`, `update`, `finish`, and `cancel`; its managed progress
  block records visible Phase and Next without changing schema 2 metadata.
- Proof supports `add`, `list`, and `show`, including file/stdin content.
- `intent list|show` discovers `explore|build|check`; `transport ...` controls
  advanced reciprocal cc/cx sessions.
- Approval gets no command or artifact. `--accept-gap` remains valid only when
  the caller already holds explicit user Approval under runtime policy.
- Existing `board status`, `work close`, `milestone close`, `evidence add`,
  `agent ...`, schema-shaped JSON fields, and internal metadata remain 3.x
  compatibility surfaces.

Help and version output are executable contracts generated by the runtime. No
board migration, runtime activation, adapter update, registry write, or
external action is implied.

## Consequences

- Ordinary use follows the same conceptual budget as the architecture.
- Maintainers retain exact storage and transport diagnostics behind advanced
  namespaces.
- Source and installed runtimes can be distinguished with `--version`.
- Schema 2 still records independent Proof as caller-asserted metadata. Strong
  authenticated provenance remains a separate future schema decision and is
  not overstated by this facade.
