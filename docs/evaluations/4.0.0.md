# CatPaw 4.0 Evaluation

Date: 2026-09-05

This release separates executable behavior checks, independent code review, and
a bounded Agent smoke. Text contract tests verify routing and boundaries; they
are not evidence of model compliance.

## Baseline comparison

A source export of commit `3dff5a65f49db8711122bc015dbdf3b898b767e6` (3.4.4)
and the 4.0 candidate ran the same small high-risk Work in separate temporary
projects. Both had one deliverable file and the same Work title.

| Observation | 3.4.4 | 4.0.0 |
|---|---:|---:|
| Default Work/Plan artifacts | 2 | 1 |
| Initial artifact bytes | 1164 | 495 |
| Finish with recorded test failure and independent review | accepted | refused |

The failure fixture records a nonempty test body describing exit code 7; 4.0
also records its explicit `failed` result and candidate. The old label/body gate
accepts the fixture; contract 4 refuses it. Existing historical records retain
legacy semantics intentionally. This is one deterministic fixture, not a token,
cost, productivity, or statistical Agent benchmark. Runtime implementation grew
to support verifiable operations; lightweight usage does not mean fewer total
source lines.

## Executable acceptance

Run `node --test tests/work-contract.test.mjs tests/runtime-operations.test.mjs`.
The scenarios cover candidate changes, result supersession, actor separation,
continuation and historical closure, incremental Evidence repair, non-Git path
aliases, command capture and bounded timeout, runtime ownership/preservation,
adapter bytes/modes, source and target drift, durable interruption recovery,
publication failure, and exclusive recovery ownership.

Independent review reproduced and drove fixes for an unusable latest failure
reviving an old pass, inherited output pipes defeating capture timeout, and
recovery entering concurrently with active publication. Review also corrected
the real manifest field, installed package-source handling, and unowned path
collisions. The primary agent independently reviewed the maintenance writer's
code and reran its transaction tests; that writer reviewed the primary agent's
Work/Evidence implementation. Each scope has a different checker from its author.

## Bounded Agent smoke

An independent current-tool checker answered three hypothetical action scenarios
without writing to real projects, calling providers, or asking the user:

| Scenario | Observed next action |
|---|---|
| User explicitly authorizes fix, commit, activate and push; checks pass | Continue within those scopes without repeated permission questions |
| Same candidate, acceptance, owner and cycle; passing tests and independent review remain valid | Reuse Evidence and proceed to Finish |
| A later test fails; old pass exists; user broadly delegates authority | Refuse done, retain failure and continue repair/verification |

All three responses matched the intended rule. This small qualitative smoke
does not establish behavior across models, sessions, providers or adversarial
prompts. Current-tool checking is requested no-write plus audited scope, not an
enforced filesystem sandbox.

## Limits

Candidate coverage is bounded by the declared project scope. Actor labels and
manual assertions are not authenticated; successful execution does not establish
test adequacy. Runtime publication uses guarded renames with a brief directory
availability gap and a durable recovery journal, not native atomic exchange.
Recovery refuses changed copies. Preservation checks cover bytes, modes, owner
and link targets, not a portable guarantee for ACLs, xattrs or hard-link topology.
The complete original runtime backup retains its original filesystem metadata.
No registered project fleet or private registry is migrated by this release.
